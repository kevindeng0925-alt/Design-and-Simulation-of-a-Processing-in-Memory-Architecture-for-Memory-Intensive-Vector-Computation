## Baseline

CPU 路径先从两个内存地址各读一个向量，然后计算，最后把结果写回目标地址。VADD 和 VMUL 写回一个长度为 N 的向量。DOT 将 N 个乘积加起来，只写回一个整数。

模型版本 `cpu-serial-word-v1`。令 W 为每个整数的字节数，R 为写回的字数（VADD/VMUL 为 N，DOT 为 1）。

```text
host-memory bytes = (2N + R) × W
cycles = startup + 2N × read + R × write + arithmetic
VADD arithmetic = N × add
VMUL arithmetic = N × mul
DOT  arithmetic = N × mul + max(N - 1, 0) × add
```

| 参数 | 默认值 | 单位 |
| --- | ---: | --- |
| 整数位宽 | 32 | bit |
| 启动 | 8 | 模拟周期 / 任务 |
| 读、写 | 4、4 | 模拟周期 / 字 |
| 加、乘 | 1、3 | 模拟周期 / 次 |

参数为课程实验的自设值。访存与计算串行相加，CPU 模型不包含缓存、SIMD、预取、流水线、访存重叠或 DRAM 通道争用。主机流量按逻辑读取和写回的有效载荷计数，排除 Python 对象占用和结果核验访问。仿真以同一个抽象周期为比较单位。Python 运行耗时属于实验工具开销，本实验未采集。

## Benchmark

每个配置由操作、长度、bank 数、卸载开销以及种子确定。三条模式各拿一个独立内存副本。核验通过后才写性能值，核验同时检查返回值和目的地址。参考答案由独立整数逻辑生成，手算单元测试另外覆盖溢出、空向量、缺失地址、错误长度、结果形态和成本。失败行保留错误信息，模式不可用则保留空指标和 `unavailable`。

| 数据集 | 长度 N | Bank 数 | 卸载开销（周期） | 种子 |
| --- | --- | --- | --- | ---: |
| Smoke | 0、2、10 | 1、4 | 0、32 | 1600 |
| 校准 | 2、10、32、128、512、2048、8192 | 1、4、8 | 0、32、128 | 1610 |
| 保留验证 | 3、11、64、256、1024、4096、16384 | 2、4、16 | 16、32、96 | 1620 |

两套正式数据集长度互斥，输入种子也不同。固定 N、改变 bank 数时可以比较并行扩展性，固定 bank 数和卸载开销时可以比较长度增长的影响。接入 Adaptive 后，只允许用校准集定模型或阈值，冻结策略后再评价保留集。首轮测试同时包含 `N < banks` 和 `N % banks != 0`。

## Results

校准集和保留验证集各含 189 个 CPU 案例，全部核验通过。每个数据集还各含 378 个 PIM/Adaptive 的 `unavailable` 行。下表取自保留验证集的 N=1024、4 banks、卸载开销 32 周期。bank 数和卸载参数用于后续对照，CPU 公式中没有这两项。

| 操作 | CPU 模拟周期 | Host-memory（bytes） |
| --- | ---: | ---: |
| VADD | 13,320 | 12,288 |
| VMUL | 15,368 | 12,288 |
| DOT | 12,299 | 8,196 |

VADD 与 VMUL 搬运的数据量相同。VMUL 每个元素额外花 2 个计算周期，所以此处多 2,048 周期。DOT 只写回一个整数，因此这里比 VADD 少写 4,092 bytes。两个已生成的图固定 4 banks 和 32 个卸载周期，横轴用对数刻度展示长度范围。曲线外观受刻度影响，原始 CPU 模型周期与流量随 N 线性增长（DOT 的空输入单独处理）。

## CPU 成本来自哪里

以下分项来自 `cpu_cost_parts`。CPU 执行器用同一组分项求总周期。N=1024、默认配置下，每行单位均为模拟周期。

| 运算 | 启动 | 输入读取 | 输出写回 | 加法 | 乘法 | 合计 | 读写占总周期 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| VADD | 8 | 8,192 | 4,096 | 1,024 | 0 | 13,320 | 92.3% |
| VMUL | 8 | 8,192 | 4,096 | 0 | 3,072 | 15,368 | 80.0% |
| DOT | 8 | 8,192 | 4 | 1,023 | 3,072 | 12,299 | 66.6% |

三者读入相同数量的字。DOT 与 VMUL 相比，省下 N−1 次写回，增加 N−1 次归约加法；N>1 时，每次写比每次加贵，DOT 的总周期就更低。与 VADD 相比，N≥1 时 DOT 多花的周期可化简为 `N × (乘法成本 − 写成本) + 写成本 − 加法成本`。默认值代入得 `3 − N`，所以 N=3 两者相等，从 N=4 起 DOT 更快。两种运算输出含义不同，这个分界描述其工作量，不能用来替换算法。[成本分解图](../../results/figures/cpu_cost_parts.png) · [逐项数据](../../results/data/cpu_study.csv)

## 参数敏感性

对 N=1、4、64、1024 和全部三种操作，固定种子 1630、数据、位宽和其他成本。每个工作负载运行 7 种配置，共 84 条。基准之外只改一个因素：读写成本联动取 2 或 8（默认各 4），乘法取 1 或 6（默认 3），启动取 0 或 32（默认 8）。读写的半倍与双倍表示单字访存变便宜或变贵；乘法下界表示与加法同成本；启动取零和较大的 32 用于检查短任务。这里扫描的是课程模型假设。

| N=1024 的设置 | VADD | VMUL | DOT | 周期从少到多 |
| --- | ---: | ---: | ---: | --- |
| 默认 | 13,320 | 15,368 | 12,299 | DOT、VADD、VMUL |
| 读写各 2 | 7,176 | 9,224 | 8,201 | VADD、DOT、VMUL |
| 读写各 8 | 25,608 | 27,656 | 20,495 | DOT、VADD、VMUL |
| 乘法 1 | 13,320 | 13,320 | 10,251 | DOT，随后 VADD 与 VMUL 并列 |
| 乘法 6 | 13,320 | 18,440 | 15,371 | VADD、DOT、VMUL |

读写成本翻倍，VADD 增加 12,288 周期（92.3%），DOT 增加 8,196 周期（66.6%）。乘法翻倍只影响 VMUL 和 DOT，各增加 3,072 周期。N=1024 时，两项修改均可改变操作间的差距；访存变便宜或乘法变贵还能翻转 VADD 与 DOT 的排序。

启动成本从 8 改为 32 时，所有任务都增加 24 周期。N=1 的 VADD 从 21 增至 45，增加 114.3%；N=1024 的 VADD 从 13,320 增至 13,344，仅增加 0.18%。默认参数下，N=1 的 VADD 启动占 38.1%，读写占 57.1%。启动改为 32 后，启动占比升至 71.1%。因此“小任务主要受启动成本影响”取决于具体的启动与读写参数。单因素扫描未考察参数交互，单字读写固定收费也限制了结果向有缓存、流水线或带宽争用的系统推广。[敏感性图](../../results/figures/cpu_sensitivity.png) · [固定配置](../../benchmarks/design.json)

## 有效配置、配对与正式验收

校准和保留验证各有 567 行（189 个计划点 × 3 种请求模式）。每套 189 条 CPU 成功记录仅代表 **21 个有效 CPU 配置**（3 种操作 × 7 个长度，CPU 参数与版本固定）。另外两维 3 个 bank 数 × 3 个卸载开销让每个 CPU 配置出现 9 次，用于与同条件的 PIM/Adaptive 配对。这些记录不能当成 9 次独立测量或置信区间依据。两个数据集长度互斥，共 1,134 行、42 个有效 CPU 配置。84 条敏感性观测另表保存。

程序按预定网格逐点检查操作、长度、bank、卸载开销、种子和实际输入摘要，还核对位宽、算术语义、整套后端版本与配置、公共周期和统计窗口。有效对照逐点报告 CPU 快、PIM 快或同周期。遇到缺点、重复或不可比数据，断开相邻区间；有多个反转时保留每个区间。平局只证明该采样点相等。没有反转且有缺口时，可说明的范围限于各连续的有效采样段。

Adaptive 针对同一点的两条固定路径评价。平局时两条选择都算正确。额外周期使用 Adaptive 总周期减两条固定路径中较小值；总周期包含决策时间，避免再加一次。负差值原样记录，并阻止通过正式验收；若声明决策开销后总时间比“所选固定路径 + 决策开销”还短，也会标记核查。可能原因包括统计窗口、时基、决策开销归属或模型的不确定性，需 C 查看执行记录。摘要区分失效、缺失、不可比和有效样本。当前正确率与平均额外周期均无可用数值。

`review_run --formal` 核对两套完整网格、Mock 标记、数据版本、图的来源清单、报告标记及已保存摘要。合成测试在临时目录验证通过和拒绝路径；其耗时没有进入交付 CSV。摘要见 [运行报告](../../results/review/run_report.md)，每个实验点见 [明细](../../results/review/points.csv)。完整命令在 [README](../../README.md)。

三模式比较待 B/C 接入。接入后固定 N=1024、卸载开销 32 周期，绘制 `speedup = CPU cycles / 比较模式 cycles`。对每个操作、bank 数和卸载开销组合，按 N 检查 `PIM cycles - CPU cycles` 的正负和零值。若相邻样点异号，报告交叉区间。若测试范围无交叉，说明是全段哪条路径更快，或哪些点缺少可用观测。当前缺少 PIM 周期，交叉点及加速比均无法计算。
